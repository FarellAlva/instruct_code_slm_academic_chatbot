1: Clone Repository
Buka Terminal / PowerShell / Command Prompt, lalu ketik:
    git clone https://github.com/FarellAlva/instruct_code.git
    
    cd instruct_code

2: Jalankan Docker Compose

    docker compose up -d --build


3. LOGIN OLLAMA CLOUD & PULL MODEL (HANYA SEKALI SEUMUR HIDUP)


menggunakan model cloud 'gemma4:31b-cloud', lakukan login sekali:

Langkah 3.1: Login ke Akun Ollama
Jalankan perintah ini di terminal:
    docker compose exec ollama ollama signin

* Akan muncul tautan login (https://ollama.com/...) di terminal.
  Buka tautan tersebut di browser Anda, login, lalu klik tombol APPROVE.

Langkah 3.2: Unduh Model Cloud
Setelah berhasil login, jalankan:
    docker compose exec ollama ollama pull gemma4:31b-cloud

* Selesai! Data login dan model ini tersimpan permanen di volume Docker
  (ollama_models). Jika komputer dimatikan atau direstart, Anda TIDAK PERLU
  login ulang.


4. AKSES APLIKASI DI BROWSER

Buka browser dan kunjungi:
    http://localhost:8501

Done...



--------------------------------------------------------------------------------
5. OPSI MODEL LOKAL (100% OFFLINE / TANPA PERLU LOGIN SAMA SEKALI)
--------------------------------------------------------------------------------
Jika komputer baru tidak memiliki akun Ollama atau ingin berjalan offline:
Cukup tarik model open-source lokal dengan perintah:
    docker compose exec ollama ollama pull gemma2:2b

Lalu di browser (http://localhost:8501), ganti teks pada kolom 'Model' di sidebar:
    gemma2:2b

6. PERINTAH PENGELOLAAN HARIAN
--------------------------------------------------------------------------------

- Melihat log / memantau error secara realtime:
    docker compose logs -f

- Melihat log khusus aplikasi chat:
    docker compose logs -f adita-chat

- Melihat log khusus Ollama:
    docker compose logs -f ollama

- Mematikan seluruh sistem:
    docker compose down

- Menyalakan kembali di kemudian hari (cepat, tanpa build ulang):
    docker compose up -d

- Cek status container yang sedang berjalan:
    docker compose ps
  *(Container 'adita-ingest' akan tampil berstatus 'Exited (0)'. Itu NORMAL —
    container ini memang hanya berjalan sekali lalu berhenti.)*

- Melihat log proses ingestion knowledge base:
    docker compose logs adita-ingest

- Membangun ULANG knowledge base dari folder data/ (tanpa scraping web):
    docker compose run --rm adita-ingest python ingest.py --clear --skip-scrape

- Mengambil data TERBARU dari website Pradita, lalu bangun ulang knowledge base:
    docker compose run --rm adita-ingest python ingest.py --clear
  *(Perintah ini butuh koneksi internet karena melakukan scraping + unduh foto.)*

  Setelah ingest ulang, nyalakan ulang aplikasi chat agar membaca data baru:
    docker compose restart adita-chat

7. TROUBLESHOOTING / KENDALA UMUM
--------------------------------------------------------------------------------

Kendala 1: Port 8501 atau 11434 sudah terpakai di komputer host
Solusi   : Buka file 'docker-compose.yml', ubah bagian ports:
           Misal dari "8501:8501" menjadi "8502:8501".
           Lalu akses via http://localhost:8502.

Kendala 2: Docker daemon error / tidak bisa konek
Solusi   : Pastikan aplikasi Docker Desktop di Windows sudah dibuka dan
           berstatus "Engine running" di pojok kiri bawah.

Kendala 3: Chatbot menjawab "tidak memiliki informasi" untuk semua pertanyaan
Solusi   : Knowledge base kemungkinan kosong / gagal dibangun. Cek log-nya:
               docker compose logs adita-ingest
           Lalu bangun ulang secara manual:
               docker compose run --rm adita-ingest python ingest.py --clear --skip-scrape

Kendala 4: Container 'adita-rag-app' tidak mau menyala
Solusi   : adita-chat sengaja menunggu 'adita-ingest' selesai dengan sukses.
           Jika ingestion gagal, aplikasi chat tidak akan dinyalakan supaya
           tidak melayani jawaban dari knowledge base kosong. Periksa:
               docker compose logs adita-ingest

Kendala 5: Perubahan data text di folder data/web tidak terbaca
Solusi   : Karena folder data/ dan chroma_db/ sudah di-mount langsung (volume bind),
           setiap perubahan file di komputer host otomatis langsung tersinkron
           ke dalam container. TETAPI file baru belum masuk ke knowledge base
           sampai di-ingest ulang:
               docker compose run --rm adita-ingest python ingest.py --clear --skip-scrape
               docker compose restart adita-chat
